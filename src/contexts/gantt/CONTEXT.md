# Gantt

Owns the `/gantt` surface: one or more **charts**, each a recursive tree of lanes over a time axis, with `blocks` arrows between them and a markdown document attachable to any lane. A chart's nodes arrive from two places **at once** — Jira tickets discovered from one or more epics and kept in step by a non-destructive sync, and lanes an agent authored for which the chart is the only copy ([ADR-0012](../../../docs/adr/0012-gantt-charts-as-a-system-of-record.md)).

It is the one context in the app that renders a **system of record** rather than a view of someone else's. Notes annotate a ticket, the watchlist curates keys, an explain report is derived and `close()` deletes it; a chart's PRD bodies exist nowhere else. CONTEXT-MAP's headline claim carries its exception for this folder and no other, and the exception is paid for in named parts rather than accepted: validation at the boundary, one writer, serialised writes, an append-only changelog, and the destructive verb kept away from the machine.

The surface is **read-only about chart content**. Expand, collapse, zoom, scroll, select a lane, read a body, refresh the mirrored half, archive the chart — and nothing that edits a plan, because the agent that maintains it is the only writer and it writes over the REST contract in `routes/api/`, not through this context.

## Language

**Chart** (kernel `GanttChart`, `server/lib/gantt-schema.ts`):
One programme of work: `{ version, id, title, jiraSources, lastSyncedAt, createdAt, nodes, edges }`. Stored **flat with `parentId`** and presented as a tree — depth is unbounded, which is a statement about the domain and not about the JSON, because node-level `PATCH` over nested children would be path-addressed tree surgery on every write and reparenting would be a move rather than a field. `id` is a slug and also the folder name under `~/.clashboard/gantt/`, so the id format **is** the path guard; `../escape` is not a slug. `jiraSources` is a list of epic **keys**, never a JQL string: the server builds `parent in (…)` itself with `assertIssueKey` over every key, so no unvalidatable query is ever stored and the SKILL teaches a string array rather than a query language.

**Node** (kernel `GanttNode`, read as `GanttNodeView`):
One lane. Its `source` is `{ kind: 'jira', key } | { kind: 'local' }`, and the sharp statement is that **source names who owns which _field_, not who owns the node**. A jira node's `title`, `column`, `status` and `assignee` are **mirrored** — sync overwrites them and nothing in the UI offers to edit them. Its `parentId`, `order`, `start`, `end`, its edges and its body are **chart-owned**, and sync never touches them. So a node is not "from Jira" or "local": it has a mirrored half and an owned half, and every rule in this context is stated against one half or the other (`MIRRORED_NODE_FIELDS` is the list; a `PATCH` naming one of those on a jira node is a `422`, because accepting a write the next sync would overwrite would be a lie).

`start` / `end` are `YYYY-MM-DD` **or `null`**, chart-owned on every node including parents, never read from Jira and never written back. Nullable because import makes them so — bootstrap creates one node per discovered ticket with no dates, and requiring them would mean fabricating a plan nobody made.

An undated lane is drawn anyway, as a **ghost** (`domain/ghost-span.ts`, [ADR-0012 §4 amendment (ii)](../../../docs/adr/0012-gantt-charts-as-a-system-of-record.md)): one week, placed the day after its latest blocker's `end` and never earlier than today, in a dashed outline with no fill. The earlier rendering — dimmed, bar-less — was honest and useless: `TO DO` and blocked lanes are the ones a reader opens a Gantt to find, and they were the blank ones, so the chart answered "where has this been" in full and "what do I work on next" not at all. The ghost is scoped so that (d) stays true: nothing is written, `GanttRow.undated` stays true so the tree still dims it and Needs attention still counts it, a real date always wins the placement, and **leaves only** — a parent already answers "when" with its child-span underlay, and a ghost over the top of that would be the chart arguing with itself. Every node carries its own span, parents included, because a purely rolled-up parent cannot express "this PRD is Q4" before it has been decomposed, which is the order planning actually happens in.

`hasBody` is **derived at read time** from the presence of `bodies/<id>.md` and never stored: a stored flag would be a second source of truth for a file's existence.

**Edge** (kernel `GanttEdge`):
`{ id, from, to, source }`, and every edge means **`from` blocks `to`**. There is no `kind` to pick — a second relation would be additive rather than a field to leave unset. An edge carries its own `source` for the same reason a node does, and here the common case is the important one: a **local** edge between two Jira tickets is the dependency an architect knows about and Jira was never told, so ownership is a field rather than something derived from the endpoints. One reconciliation rule — a local edge whose endpoint pair later turns up as a real Jira link is **promoted** to `jira`, not drawn twice.

**Column** (kernel `Column`, via `columnForStatus`):
Progress, and the board's own vocabulary rather than a second one: `TO DO | In Implementation | In Code Review | Done`, derived for a jira node from its real status name and declared for a local one. Reusing it is deliberate — it is already case-insensitive over HDR's mixed casing, and a second progress vocabulary would be a second answer to one question. A **percent** was rejected outright: a number an agent invents, never revises, and the view renders as a confident partial bar.

A **leaf bar is toned by its real `status`** rather than by its column, from `widgets/status-pill`'s `styleForStatus` — read, not re-picked, because a bar and the chip on the same ticket's card disagreeing about what `IN UAT` is would be two answers to one question. The column is still the grouping; what the status buys back is the four distinctions `Column` folds away (`In STG` / `In QA` / `In UAT` / `Done` into one tone, `Blocked` into `TO DO`'s grey), which are the ones a reader scanning a release wants. A lane with no status of its own — every local lane — borrows its column's chip colour, so the two cannot drift apart.

Those four are distinguished by **lightness within one green** rather than by four hues (green-700 → 400, brightening towards `Done`). Four unrelated hues is what the palette had, and a chart of mostly-finished work rendered it as a parade; one hue says "further along the same pipeline", which is what the four statuses actually are. Statuses _before_ STG keep their own hues, because those are different kinds of state rather than steps along one.

A parent summarises its descendants as a **distribution, not a state** — a segmented bar plus `7 of 11 done`. Any single rolled-up state hides the answer the chart was opened for: "In Implementation" over eleven features could be one started and ten untouched, or ten shipped and one in review.

**blocked / unresolvable** (`domain/blocked.ts`):
`Column` costs exactly one thing here — `COLUMN_TO_STATUSES` folds `Blocked` into `TO DO`, erasing the one state a dependency chart is about — and this is where it is paid back. A node is **blocked** when something pointing at it through a `blocks` edge is not `Done`, and **unresolvable** when it sits in a cycle. Both are **derived from the edge graph and never stored**, so neither can go stale when the blocker ships, and the arrows become load-bearing rather than decorative. Drawn as a ring around the bar rather than a colour in it, because the fill already means progress.

A **cycle** (`domain/cycles.ts`) is always recorded and then surfaced: the API never refuses to record a dependency someone declared — an agent building a chart incrementally will create a cycle it intends to resolve two calls later — so the layout detects it, the warning names the loop in order by title, and its edges render dashed. A plan that is impossible must **look** impossible; that is the most expensive thing a planning view can get wrong.

**Child span and overflow** (`domain/child-span.ts`):
The derived underlay beneath a parent's bar, computed from its **dated descendants only**. It is drawn whether or not it leaves the declared window, because "this PRD is Q4 and its features are Q4" is worth seeing — but when it runs past the parent's own `end` it is `overflow` and toned differently. That is the point of drawing it at all: a PRD whose features have slipped shows the **overrun** instead of silently absorbing it.

**Needs attention** (`view-model` `GanttNeedsAttention`):
The three things a chart is waiting on a human or an agent to fix, in **one line**: lanes with no dates, lanes nobody placed, and tickets that left their epic. One line rather than three badges because one instruction to an agent fixes all of it, and a count split across the chart is a count nobody adds up. `unplacedAtRoot` is the judgement in it — a root lane someone _chose_ is not unplaced, so what counts is a node whose `parentId` named something not in the chart, and a **childless jira node still sitting where import dropped it**; a jira lane at the root with children under it is doing a PRD lane's job and is left alone. This line is what ADR-0012 §8's "unplaced tray" became, and it is read-only for the same reason the tray was: the agent can read a ticket to decide where it belongs, so the agent does the placing.

**The layout function** (`view-model/gantt-layout.ts`):
`layout(chart, { zoom, collapsed, expandedInfo, visibleRange, today, selected }) → { ticks, axisWidth, rows, bars, childSpans, arrows, selection, cycles, needsAttention, todayX }`. Pure, table-tested, **no React import** — the repo's strongest evidence for ADR-0003, since a Gantt layout is the kind of thing a library is normally reached for and a library would have taken the demonstration away. Two of its dimensions have files of their own, split along the obvious seams: `gantt-axis.ts` owns time, `gantt-arrows.ts` owns what-waits-on-what, and `gantt-needs-attention.ts` owns the one question with no position at all.

Every position is a **fraction of the axis**, which is what keeps the chart free of a `ResizeObserver`: `left: 42%` means the same at every width, so a resize is a repaint. `axisWidth` is the single exception and it points the other way — not a measurement taken from the DOM but a width handed **to** it, `days × DAY_WIDTH[zoom]`, so the bar region can be wider than the viewport and scroll. Zoom therefore changes density rather than only tick labels, which is the fix for one fourteen-week lane compressing thirty others into a few pixels each ([§10 amendment (iii)](../../../docs/adr/0012-gantt-charts-as-a-system-of-record.md)). The domain is padded by one whole unit of the zoom each side, so there is calendar to scroll into before the plan starts and after it ends. Row heights are **constants, not measurements**, because the arrow overlay works out where a row sits by counting the rows above it. `visibleRange` is there from inception so that the day a three-hundred-node chart arrives, row windowing is a change to one caller rather than to this function.

**Selection and the waterfall** (`view-model/gantt-arrows.ts`):
A chart at rest draws **no arrows**. The first real one carried 54 edges over 30 lanes, which is a thicket a reader cannot trace one dependency out of, so the arrows wait to be asked for: clicking a **bar** selects that lane and lights its whole waterfall — everything upstream and everything downstream, **transitively** — while the lanes outside it dim. The closure is _directed_ rather than over the connected component, because on a graph this dense an undirected walk lights the whole chart and puts the thicket straight back; a lane that merely shares a blocker with the chain stays dark. One arrow is never hidden: a **cycle** edge, because §6 requires a plan that cannot execute to _look_ impossible and an edge the reader has to discover by clicking is not that. The gesture is on the bar and not the lane title, which still opens the ticket — two gestures, two targets. The header names the selection and carries the dismiss, since a mostly-faded chart with no visible undo is worse than the thicket.

This does not reopen re-anchoring below. Collapse never removes a dependency from the graph, it restates it at a coarser altitude; selection changes only which part of that graph is on screen now, and the waterfall is taken over the **re-anchored** pairs so the two rules compose.

**Re-anchoring** (the projection step inside `layout`):
An arrow whose endpoint is collapsed out of view **attaches to its nearest visible ancestor** rather than disappearing, and arrows that land on the same pair **merge with a `count`**. Collapse then _summarises_ dependencies instead of concealing them, and a fully collapsed chart becomes a PRD-level dependency graph — arguably the most useful view of all. Hiding the arrow was rejected because collapsing a lane would then silently destroy information, so the chart could only be trusted fully expanded, which defeats collapse. An edge between two children of one collapsed parent re-anchors to a self-loop and is **dropped**, because a self-arrow communicates nothing. An arrow needs two **bars**: an endpoint with no dates has no position on the time axis, so it is left undrawn rather than parked at day zero where it would assert a dependency on a date nobody set — and that lane is already named in Needs attention.

**Authoritative discovery** (`server/contexts/gantt/application/sync-chart.ts`):
Whether one discovery search can be read as the whole epic. It matters because marking a node `orphaned` is an argument from **absence** — the key was not in the result — and an argument from absence is only valid over a complete result. Two results are not authoritative: a **truncated** search (the gateway caps at 100 and does not page, so `nextPageToken` / `isLast` say so rather than a count inferring it) and an **empty** result against real sources (an epic whose every child has genuinely left is possible and vanishingly rare; a mistyped key, a renamed project and an odd answer from Jira look identical). When discovery is not authoritative the orphan list is dropped and nothing else is: additions and mirror refreshes are arguments from **presence**, and this search did see those tickets.

**One writer** (ADR-0012 §8):
The agent maintains the plan; this surface reads it. There is no control here a reader could mistake for an editor — no drag to reschedule, no reparent, no arrow to draw, no title to edit, no body to write — and the asymmetry is stated on both sides, in the SKILL the agent is handed and in the surface it describes. The two verbs the UI does have are not exceptions: **sync** writes only the mirrored half Jira owns, and **archive** does not write a chart at all, it moves the folder. Node ids are agent-supplied **slugs** rather than server-generated opaque ids so that an agent can address a node across many turns without carrying a map it cannot reconstruct, and so `bodies/tier-migration.md` is a file a person can open. `DELETE /charts/:chartId` is deliberately **not exposed**: single-writer is a rule about chart _content_, and the irreversible verb over a system of record belongs with the human rather than with a process acting on paraphrased instructions.

_Avoid_: "task" for a node (a lane is a PRD, a feature or a ticket at any depth; "task" imports a flat work-breakdown vocabulary this chart does not have, and collides with Jira's issue type); "progress" as a **percentage** (progress is a `Column`, and for a parent a distribution with an `n of m` — the percent was rejected, not omitted); "delete" for **archive** (archiving moves the folder to `gantt/.archive/`; nothing in this context erases anything, and the API has no delete verb for a chart at all); "sync" for the **initial import** (bootstrap and sync are one code path, which is why there is no `import` verb to rot beside `sync` — but the first fill _places_ nodes by Jira's parent, and sync never places anything again); "blocked" as a column (it is derived, and folding it into `TO DO` is the thing deriving it works around); and "task bar" or "milestone" for a bar, which this chart has no concept of.

## Use-cases

There is **no context-local application service**. As in `explain` and `bulk-refine`, both halves are coordinator hooks over server functions, and Jira is never reached from here — `gantt-application-only-imports-kernel-and-self` is declared from inception anyway, so one cannot appear without the boundary already enforced.

| What            | Coordinator hook       | Server function     | Notes                                                                                                                                                                                                                                                  |
| --------------- | ---------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| the chart list  | `useGanttCharts`       | `listGanttCharts`   | Store **summaries** — header fields plus two counts — not charts. A list of twenty charts must not carry every node in all of them.                                                                                                                    |
| one chart       | `useGanttChart`        | `getGanttChart`     | The skeleton with `hasBody` per node and no bodies, so a row of titles does not ship every PRD behind it.                                                                                                                                              |
| one lane's body | `useGanttBody`         | `getGanttBody`      | Fetched **only while a band is open**, gated on the ids rather than a boolean, so a closed band costs nothing and a reopened one is free.                                                                                                              |
| the audit trail | `useGanttChangelog`    | `getGanttChangelog` | "What has the agent been doing to my plan" — part of the visibility the feature exists for, not a debugging aid. Oldest first as stored, because the file is append-only; `useChartChangelog` reverses it, so the popover opens on what just happened. |
| refresh         | `useSyncGanttChart`    | `syncGanttChart`    | The header's Refresh **and** the stale-on-open trigger, which is one mutation so neither can run while the other is. Absent entirely on a chart with no epics behind it.                                                                               |
| archive         | `useArchiveGanttChart` | `archiveGanttChart` | The one irreversible verb, behind a confirmation that names the chart, and deliberately absent from the REST surface.                                                                                                                                  |
| the SKILL       | `useGanttSkill`        | `getGanttSkill`     | The whole document with this server's **origin** and the open chart's id already substituted — the origin read from the request, because the one thing a pasted SKILL must get right is the URL.                                                       |
| the key index   | `useGanttKeyIndex`     | `getGanttKeyIndex`  | Jira key → the lane that carries it. The palette's legality input for `g`, read by `routes/-command-palette/`, never by this context.                                                                                                                  |

The read side runs on the server's `readOnlyStoreDeps()` — the live store with every write verb replaced by a rejecting one. That is not tidiness: one writer is a promise this surface makes, and a refusing dep makes a write reached through a server function a rejected promise rather than a comment.

> **The SKILL is half of the API contract.** The schema says what a body may be; `.claude/skills/clashboard-gantt/SKILL.md` is the only place an agent learns the field **names**, the slug rule, that dates are `YYYY-MM-DD` or `null`, that mirrored fields must not be patched on a jira node, and that `DELETE /charts` does not exist. Two structural tests keep it honest: every required field of the schema must be named somewhere in the text, and every literal `curl` body in it must validate against the real request schemas. `explain-skill.test.ts`'s comment records what the absence of such a test costs — a twenty-minute run rejected at the boundary over a field the instructions no longer mentioned.

> **The API lives only while `vite dev` does.** There is no `start` script, no daemon, no auth, localhost only. The SKILL's **first** instruction is therefore to probe `GET /api/gantt/charts` and, on connection-refused, stop and report that clashboard is not running — because an agent that queued the work or fell back to writing the files directly would bypass the write queue, the validation and the audit trail that exist to pay for §1's exception.

## View-model state machine

`GanttState` is `{ zoom, collapsed, expandedInfo, revealed, selected }`; `reduce(state, event)` is exhaustive over its event union with `ts-pattern`, so a new event is a compile error until every arm handles it.

- **The chart is not in here.** It is server state owned by the query cache, and the only thing this file needs from one is its **extent**, once, to pick the opening zoom: six weeks or less opens at `week`, nine months or less at `month`, longer at `quarter`. Three fixed zooms rather than continuous, because the tick-density algorithm is the fiddliest code in any timeline and the hardest to make look deliberate at every scale.
- **A chart opens with nothing collapsed.** Lanes arriving folded would hide the decomposition the reader came to see, and the PRD-level view is one press away and worth arriving at on purpose. `allCollapsed` folds one level per press, from the outside in.
- **Nor is `selected`.** It is the answer to "what does this lane wait on", asked a moment ago, so `gantt-preference.ts` does not persist it either — a chart that reopened with last week's waterfall lit up would be asserting a focus nobody currently has.
- **`revealed` is not a preference.** It is the lane a hand-off asked for (`?node=`, the palette's `g`), so `gantt-preference.ts` does not persist it and the route consumes the search param with `replace` — a refresh must not re-announce a lane the reader has already been shown, and the back button must not land on the reveal either.
- **Collapse, bands and zoom are per-viewer `localStorage`**, keyed by chart id, following ADR-0007's precedent for lane collapse — never fields in `chart.json` an agent could fight with.
- **The stale-on-open sync is a mutation guarded on the query's data, not an effect** (`use-stale-sync.ts`). An effect would fire after a render that already drew the stale chart, would need a dependency array naming the very value the sync changes, and would still need the same guard to stop the loop. `isSyncStale` is the pure rule, and it also answers "never for a chart with no epics behind it".

## Cross-context dependencies

- `~/kernel` — `GanttChart`, `GanttNode`, `GanttEdge`, their `source` unions, `GanttChartView` / `GanttNodeView` / `GanttChartSummary` / `GanttChangelogEntry`, `Column` and `COLUMNS`, plus the eight server-function result types. Types only, which here has a second edge beyond the rule `kernel/explain.ts` states: a client module that could reach a body schema would be holding a tool for a job it is not allowed to do.
- `~/coordinator` — the eight hooks above (presenter only).
- `~/design-system` — the `Dialog` family only: the band's escape to a full view, and the archive confirmation. The changelog is a local toggled panel rather than a dialog, because nothing behind it needs to be blocked while it is open.
- `~/widgets/status-pill` — `styleForStatus` only, and only in `view/GanttBar.tsx`. The one import that is not a type: a bar is toned by the same palette as the chip on the ticket's card, because two answers to "what colour is `IN UAT`" is one too many. Permitted by the dependency law (`contexts/<name>` → `widgets/<name>`) and precedented by Detail's `Relationships.tsx`.
- `~/lib` — `cn`, `testIds` (view only).
- `sonner` — one toast each for "SKILL copied" and "chart archived", which are the two actions with no visible result on the chart itself.
- `react-markdown` + `remark-gfm` — the band's own prose styling, **not** Detail's `NotesMarkdown` and not Explain's: a PRD is wider-set than either, and reaching into another context for a style sheet is exactly what the no-cross-context law forbids.
- `date-fns` — `formatDistanceToNow` on a list row, and the local calendar day injected into `layout`. A chart date is the day a person means, not the UTC one.

No imports from `~/contexts/<other>`, in either direction. The palette reaches a lane by **navigating** to `/gantt?chart=<id>&node=<id>` and Detail's panel arrives over the chart through `?issue=<KEY>` into the chrome's `overlay` — two URL hand-offs rather than a shared object, which is ADR-0009 §3's mechanism one surface over.

Pinned by `gantt-domain-only-imports-kernel`, `gantt-application-only-imports-kernel-and-self`, and `gantt-view-model-only-imports-kernel-and-domain`.

## Public surface

```ts
export { ChartList, GanttChartView } from './view'
```

Two components, and **no presenter**. Explain exports `useExplain` because its shell owns the tab selection; a chart's whole state is the reader's own — collapse, bands, zoom — and belongs inside, so `routes/-gantt/GanttShell.tsx` hands down a chart id and gets back a rendered chart. The layout function, the state machine and the five domain rules are internal: they are the context's centre of gravity and nothing outside it has a use for them.
